MD Rewriter - User guide

MD Rewriter reads and writes Sega Mega Drive / Genesis cartridges through the MD Rewriter USB device. With it you can back up games and saves to your computer, write games to rewritable flash cartridges, and compare files.

Jump to: Quick start · Recipes · What the log says · Troubleshooting · Safety

Quick start

  1. Plug the MD Rewriter into the computer with a USB data cable, then insert the cartridge (see Safety).
  2. In Connection, pick the device port. It is selected automatically when it is recognised (USB id 0483:5740, "STM32 Virtual ComPort"). The list refreshes by itself; press Refresh if needed.
  3. Press Connect. The log shows Device identified. and the action buttons turn on.
  4. Press Detect cartridge to check that the device sees the cartridge.
  5. Pick what you want to do: back up a game, write a game, handle saves, erase, or compare files.

Recipes (common use cases)

Back up a game

  1. Connect and press Detect cartridge if you like.
  2. Set Cartridge size to the real size of the ROM (512 KiB, 1 MiB, 2 MiB or 4 MiB). The size is usually printed in the game's documentation or listed in a ROM database.
  3. Press Read ROM... and choose a file name (.bin).
  4. Wait for 100%. The log shows Read complete and Saved to "...".

The file only appears when the read finished completely. If you cancel, or anything goes wrong, no partial file is left, and an existing file with the same name is not touched.

Tip: if you are not sure about the size, check the result: a wrong size that is too large may give a file that repeats itself or contains unrelated data. Compare with a known-good ROM (see Verify).

Check that a dump is correct

  1. Press Compare files..., pick your dump, then pick a known-good ROM of the same game.
  2. The log says The two files are identical, or lists how many bytes differ and the offsets of the first 20.

Dumping the same cartridge twice and comparing the two files is a good test of the cable and the contacts.

Write a game to a flash cartridge

  1. Erase first unless the cartridge is blank (see Erase). Flash memory can only change bits from 1 to 0; writing over old data without erasing gives a corrupted game.
  2. Press Write ROM... and choose the file. Any ROM from 512 bytes to 4 MiB with an even size is accepted, including 256 KiB, 768 KiB or 1.5 MiB games: it is written as it is and the rest of the chip stays blank. .bin, .md and .gen files are written as they are; .smd (Super Magic Drive) files are converted to a plain ROM automatically. If the ROM header looks wrong (no SEGA, bad checksum, truncated file) the program warns you before writing, but never blocks the write.
  3. Confirm the warning. The progress bar fills as blocks are written.
  4. Wait for Game written.
  5. Verify: leave Verify after writing ticked (it is on by default). When the write ends the program reads the cartridge back and compares it with the file; the log says Verified or gives the first offset that differs. You can also press Read ROM... with the same size and use Compare files... against the original.

Cancel during a write leaves the cartridge with a partial image. Erase and write again.

Only rewritable flash cartridges that take the standard AMD/JEDEC commands can be written. The chip the firmware was made for is shown by Detect cartridge as FLASHID:C2CB, MX29LV640EB MD FLASH CART. Other chips of the same family (for example the ST M29W640) print NO FIND NGP CARD but the program names them from the ID; they should work, although this has not been tested on hardware. Always keep Verify after writing on with such a cartridge.

Back up, restore and move saves

  1. Set Save size to the size of the game's save memory: 32 KiB or 8 KiB. If you are not sure, check the game's documentation or a game database; do not guess when you are going to write a save back.
  2. Read save... copies the saves to a .srm file.
  3. Write save... replaces the cartridge saves with a file of exactly 8 KiB or 32 KiB.

Always read the current save first and keep that file: writing a save replaces everything that is on the cartridge.

To move a save to another cartridge of the same game, read it from the first and write it to the second. Only battery-backed SRAM saves are supported; games that store saves in EEPROM or in the flash chip itself cannot be read or written with this device.

Before you erase or reflash a flash cartridge that holds a game with a battery save, read the save first.

Erase a cartridge

  • Erase by size... - erases only the sectors covered by Cartridge size. Faster: use it before writing a ROM of that size or smaller. The progress bar fills as sectors are erased.
  • Erase all... - erases the whole flash chip and the save memory. It can take several minutes, shows a moving bar and cannot be cancelled. Do not unplug the device until the log says Erase complete.

Both ask for confirmation because they destroy data. There is no undo.

Identify a cartridge

Detect cartridge prints the chip ID. A recognised flash cartridge shows FLASHID:C2CB and MX29LV640EB MD FLASH CART. For a normal (non-flash) game cartridge the message is NO FIND NGP CARD: that is expected, you can still read it. The program also says in plain words what it found: a chip it knows, or "Chip not in the list" with the ID. NO FIND NGP CARD only means the firmware did not recognise the chip; it never blocks anything.

Compare any two files (no device needed)

Compare files... works without a connection. Typical uses: check a dump against a reference, see exactly which bytes a patch or ROM hack changes (original versus patched), or confirm that a write was successful.

  • Result identical: same size, same bytes.
  • Otherwise the log gives the number of differences, a note if the sizes differ, and the first 20 offsets in decimal and hexadecimal.

Troubleshooting

Linux: "permission denied" when connecting

Your user must be allowed to use the serial port. Either add yourself to the dialout group and log in again:

sudo usermod -aG dialout $USER

or install the udev rule that ships with the program (99-md-rewriter.rules), then replug the device:

sudo cp 99-md-rewriter.rules /etc/udev/rules.d/ && sudo udevadm control --reload && sudo udevadm trigger

If the port is "busy", another program (often ModemManager) has it. The udev rule tells ModemManager to ignore the device.

The port does not appear

  • Use a USB cable that carries data; many cables only charge.
  • Replug the device and press Refresh. The list also refreshes by itself every two seconds while disconnected.
  • Windows: the device appears as a COM port. Install the "STM32 Virtual ComPort" driver if Windows does not recognise it.
  • For a port the system does not list (a symlink or a pseudo-terminal), start the program with MD_REWRITER_EXTRA_PORT=/path/to/port.

Connected, but "the device did not answer"

Wrong port, or no firmware on the device. Choose the entry that mentions 0483:5740. If you have several serial devices, unplug the others.

Reads are incomplete, out of sync or give different files each time

  • Clean the cartridge contacts (isopropyl alcohol) and make sure it is fully inserted.
  • Try another USB port directly on the computer (no hub) and another cable.
  • Dump twice and compare the two files. If they differ, the problem is the connection, not the game.
  • Check that Cartridge size matches the real ROM size.

The game does not boot after writing

  • Did you erase first? Write over old data gives a corrupted game.
  • Does the file work in an emulator? (.smd files are converted automatically, but a bad dump will not boot.)
  • Read the cartridge back and compare it with the file. If they differ, repeat with another cable and check the contacts.
  • The game may need a save mapper or a different cartridge type that the flash cartridge does not provide.

"NO FIND NGP CARD" on a flash cartridge

The firmware only recognises one chip, so it prints this for every other chip. Read the line the program adds below it: if it names a chip (for example M29W640DB), the cartridge is probably fine; if it says "Chip not in the list", the cartridge may not be flash or may not be inserted properly. Reinsert, clean the contacts, press Detect cartridge again. Test a new flash cartridge by erasing, writing a small ROM with Verify after writing on and checking that it passes.

I closed the program or lost power during an operation

Reading: nothing was saved, just read again. Writing or erasing: the cartridge is in an unknown state. Erase it and write again. Saves: restore the save file you backed up.

Safety and good practice

  • Back up first. Read the ROM and the save of a cartridge before you erase or write anything on it.
  • Never unplug the device, or remove the cartridge, while an operation is running, especially erase and write.
  • Plug and unplug cartridges with the USB cable disconnected; this is the safe way to treat any cartridge slot.
  • Erase and write operations destroy data and cannot be undone. The program asks for confirmation each time.
  • Keep Verify after writing on: it reads every write back and compares it.
  • Only copy games and saves that you own or are allowed to copy.

Technical notes

  • Link: USB virtual serial port, 1,000,000 baud, 8 data bits, no parity, 1 stop bit, no flow control.
  • ROM dump sizes: 512 KiB, 1 MiB, 2 MiB, 4 MiB. Write sizes: any even size from 512 bytes to 4 MiB. Save sizes: 8 KiB, 32 KiB. Cartridges larger than 4 MiB are not supported.
  • Data is written in 1 KiB blocks, each one acknowledged by the device before the next is sent. The last block of a file is padded with 0xFF (which means "do not program" for flash).
  • Reads are saved atomically: the program writes a temporary file and renames it only when the read is complete.
  • The program works with firmware 1.0 and newer. Some messages (erase timeouts) only appear with the updated firmware.
