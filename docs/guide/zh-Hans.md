# MD Rewriter：从开箱到第一个游戏的分步指南

**语言：** [English](en.md) · [Português (Brasil)](pt-BR.md) · [Русский](ru.md) · [简体中文](zh-Hans.md) · [हिन्दी](hi.md) · [اردو](ur.md)

写给刚拿到 MD Rewriter 开发板、对电子知识了解不多的人。这里的所有操作都在一台真实设备上完成（2026-11-13），结果见第 9 节。如果你看到的情况与文中不符，请先停下来，阅读第 10 节再继续。

**简述。** 开发板出厂的固件 1.0 可以直接使用（不需要焊接）。固件 1.1 是可选的：它能一次写好闪存卡并识别更多芯片，但安装它需要在板上焊一排小插针、一个 ST-Link V2 编程器，以及大约一小时。**KY / FlashKit 系列闪存卡最多只能存放 2 MiB 的游戏（第 8 节）。**

---

## 0. 安全规则

1. **绝不要对原装游戏卡带写入、擦除或“试一试”**（随游戏出售的那种）。它们是掩膜 ROM，无法写入，尝试只会造成损坏。程序可以安全地读取它们，对它们也只做这一件事。
2. **同一时间只用一个电源。** 要么用开发板自己的 USB 线，要么用 ST-Link 的 3.3 V 线，绝不能两个同时用。
3. **只在拔掉 USB 线的情况下插入或取出卡带。**
4. **擦除或覆盖任何东西之前先备份**（存有游戏的闪存卡，以及开发板的固件）。
5. 烙铁会烫伤人（约 350 °C）。在通风处工作，焊接后洗手（焊锡可能含铅），收起前让烙铁冷却。
6. 拿开发板之前先摸一下接地的金属物体，不要抓着卡带插槽拿。

## 3. 焊接

只有要安装固件 1.1（第 6 节）时才需要焊接。如果保留出厂固件，直接跳到第 4 节。

### 3.1 SWD 排针（4 针）

四个焊盘从上到下（USB-C 接口在板子下方）：

```
   ●  3V3
   ●  SWCLK
   ●  SWDIO
   ●  GND
 [USB-C]
```

**焊接前。** 断开一切连接。用万用表确认焊盘（开发板不通电）：

1. 蜂鸣档：一支表笔接最下面的焊盘（GND），另一支接 USB-C 接口的金属外壳。必须响。如果不响，说明焊盘找错了，或者板子放反了。
2. 之后插上 USB 线时，最上面的焊盘相对于 GND 应为 3.3 V。

**焊接步骤：**

1. 用胶带把开发板固定在桌上，正面朝上。对照正面照片找到四个孔。
2. 把 1×4 排针从上面插入孔中，短针朝下，塑料座贴在板上。四根针必须垂直、齐平。
3. 把板子翻过来。烙铁加热到约 330 至 350 °C，在湿海绵上清洁烙铁头。
4. 烙铁头同时接触针脚和焊盘（约一秒），然后把焊锡送到焊点上（不是送到烙铁头上）1 到 2 秒，先移开焊锡，再移开烙铁。先只焊一根针。
5. 检查：焊点应当光亮、呈小火山形，包住焊盘和针脚。如果发暗、发灰、成球状或有缝隙，加一点新焊锡重新加热，或用吸锡带清除后重焊。
6. 确认排针仍然垂直、齐平。如需调整，重新加热第一个焊点并同时按正。然后焊其余三根针（每根约 3 秒，不要更久：过热会让焊盘脱落）。
7. 用异丙醇和刷子清洁板子。用放大镜或手机摄像头检查四个焊点：相邻针脚之间没有锡桥，没有空隙。
8. **用万用表检查，开发板断电：**
   - GND 焊盘：蜂鸣档到 USB-C 外壳（同前）。
   - 相邻针脚之间（3V3 与 SWCLK，SWCLK 与 SWDIO，SWDIO 与 GND）**不能**响。响了说明有锡桥：用吸锡带清除。
   - 用指甲拨动每根针：都不能晃动。**第一台设备上一根松动的 GND 针让我们耗了好几个小时**（与 ST-Link 的连接每隔几分钟就断，看起来像软件故障）。如果有任何晃动，重新加热那根针。

### 3.2 USB-C：线材

V1.0 开发板的 USB-C 接口在 CC 线上没有 5.1 kΩ 电阻（`docs/HARDWARE_REVIEW.md` 中的问题 H1）。因此 USB-C 转 USB-C 的线连接到充电器或较新的笔记本时，可能**得不到供电**。请使用**带数据线的 USB-A 转 USB-C 线**，它一定能用。有经验的用户可以自行修复：把两个 5.1 kΩ 的 0603 电阻从接口的 A5 和 B5 焊盘焊到 GND；如果你不会焊 0603 元件，就用 A 转 C 线。

## 4. 组装与拆卸

### 4.1 组装（全部断电）

**正常使用**（不涉及固件）：把 USB 线接到开发板和电脑，然后插入卡带（4.3）。

**安装固件**（第 6 节）：先连接 ST-Link，此时开发板的 USB 线**必须拔掉**，卡带插槽**必须是空的**。

1. 接好杜邦线之后，才把 ST-Link 插到电脑的 USB 口。
2. 杜邦线永远按 ST-Link 上印的名称连接，不要按颜色或位置（仿制品型号各不相同）：

| 排针（从上到下） | 网络 | ST-Link 线 |
|------------------|------|------------|
| 1 | 3V3 | `3.3V`（见下面的供电说明） |
| 2 | SWCLK | `SWCLK` |
| 3 | SWDIO | `SWDIO`（有些仿制品印作 `SWIO`） |
| 4 | GND | `GND` |
| 无 | NRST | `RST` 悬空：开发板没有 NRST 焊盘 |

ST-Link 的 `5V` 脚不接。

**供电说明。** 推荐方式，在测试台上很稳定：只接 `GND`、`SWCLK` 和 `SWDIO`，**不接** `3.3V` 线，开发板由自己的 USB 线供电。如果无法把开发板接到电脑，就改用 `3.3V` 线，同时拔掉 USB 线并保持插槽为空；仿制品的 3.3 V 输出很弱，所以测试要简短。

3. 再检查一遍四根连线。用手指按一按每个杜邦头：接触不良是最常见的问题。

### 4.2 工作结束后的拆卸

1. 关闭程序。2. 拔掉开发板的 USB 线。3. 等几秒，指示灯熄灭。4. 取出卡带（4.3）。5. 把杜邦头从排针上**捏着塑料壳垂直拔出**，绝不要拽线。6. 把 ST-Link 从电脑上拔下。

排针可以留在板上，没有坏处。如果要取下：加热一根针，用钳子拔出；或者用斜口钳剪断塑料座，再逐根取下针；用吸锡带清理孔。焊盘加热不要超过几秒：会脱落。把开发板放在防静电袋或盒子里保存，远离金属。

### 4.3 插入和取出卡带

- 必须在**拔掉 USB 线**的情况下操作。
- 捏住卡带塑料壳，让**标签朝向板上“CART FRONT”箭头**所指的方向。垂直向下压入插槽直到底，用力均匀，不要摇晃或扭转。
- 取出时垂直向上拔，同样要先拔掉 USB。不要拉开发板或 USB 线。
- 开发板通电时不要换卡带：卡带和开发板共用同一组信号线，可能损坏。

## 5. 安装程序

按 README 中“安装软件”一节操作（Linux：发布页的 `.deb` 或 tar.gz，或从源码编译；Windows：从源码编译）。在 Linux 上要让你的用户可以访问串口：`sudo usermod -aG dialout $USER` 然后重新登录，或者安装 udev 规则 `Software/linux/99-md-rewriter.rules`。

确认程序能与开发板通信：接上开发板（不插卡带），运行程序，点击 **Refresh**，再点击 **Connect**。日志中会显示 `Device identified.`。命令行：

```
mdrewriter-cli ports        # 开发板显示为 0483:5740
mdrewriter-cli info         # 显示固件版本
```

如果提示“permission denied”，修正串口权限（见上）。如果看不到开发板，换一根线（带数据线的）。

## 6. 安装固件 1.1（可选，约一小时）

原因：使用固件 1.0 时，写入 S29GL064N 闪存卡会让一半的字保持空白（它隔一个字才编程一个），需要八轮修复。固件 1.1 一次就能写入并校验游戏，并且能识别芯片名称。固件 1.1 是加入了编程等待的同一个程序；它已在第一台设备上测试过（第 9 节）。

你需要 ST-Link V2、焊好的排针（第 3 节）以及程序 `st-info` 和 `st-flash`（Linux：`sudo apt install stlink-tools`）。辅助脚本 `tools/swd/swd.sh` 需要带 `bash` 的 Linux 或 macOS。Windows 上请手动执行相同的命令（6.5）。

### 6.1 接线

见 4.1 节：连接 `GND`、`SWCLK`、`SWDIO`，开发板的 USB 线已插好，卡带插槽为空。

### 6.2 测试连接

```
tools/swd/swd.sh probe
```

预期结果：`swd: probe ok (0x414, 524288 bytes)`（我们的设备使用 512 KiB 的 STM32F103xE；`0x410` 和 131072 字节也可以）。出现 `chip id 0x0` 或 “no ST-Link found” 说明连接不好：**先检查排针上的 GND**，然后是 SWCLK 和 SWDIO（如果始终连不上，把这两根对调），最后检查线材。脚本会自动重试断开的连接。

### 6.3 备份出厂固件

```
tools/swd/swd.sh backup --out ~/md_rewriter_backups/fw-factory
```

它会读取芯片两次，比较两次读数，然后写出 `fw-factory.bin` 和一个 `.sha256` 文件。**如果提示读取内容为空，请停止**：读保护已开启，无法保存出厂固件；不要擦除也不要烧录。把备份复制到第二个位置（另一块硬盘或 U 盘）。

### 6.4 写入固件 1.1

从本仓库的发布页下载 `md-rewriter-firmware-1.1.0.bin`（和 `.sha256`），用 `sha256sum -c` 校验，然后：

```
tools/swd/swd.sh flash md-rewriter-firmware-1.1.0.bin --backup ~/md_rewriter_backups/fw-factory/fw-factory.bin --yes
```

脚本会确认芯片里仍然是备份过的固件，然后写入、读回并比较，以 `written and verified` 结束。之后**拔掉再插上开发板的 USB 线**（软件复位不一定能让开发板在 USB 上重新枚举）。测试：`mdrewriter-cli info` 必须显示 `firmware 1.1.0`。

**要回到出厂固件：** `tools/swd/swd.sh restore --backup ~/md_rewriter_backups/fw-factory/fw-factory.bin --yes`。

### 6.5 Windows（手动）

安装 ST-Link 工具（带 `st-info.exe` 和 `st-flash.exe` 的 `stlink` 发布包，或 STM32CubeProgrammer）。等效命令：`st-info --probe`；`st-flash read backup.bin 0x08000000 0x80000`（如果 `st-info` 显示 128 KiB 则用 `0x20000`）；`st-flash write md-rewriter-firmware-1.1.0.bin 0x08000000`；读回后与文件的开头字节比较。请妥善保管备份。

## 7. 逐步测试你的设备

每一步都可以在图形程序（GUI）或命令行（CLI）中完成，结果相同。CLI 示例中端口会自动查找；如果有多个串口设备，请加上 `--port /dev/ttyACM0`（Linux）或 `--port COM3`（Windows）。按钮名称使用英文，因为程序没有中文翻译（有英文和葡萄牙语）。

请按这个顺序测试。如果某一步失败，停下来并阅读第 10 节。

| 编号 | 测试 | GUI | CLI | 你应该看到 |
|------|------|-----|-----|------------|
| 1 | 版本（不插卡带） | **Connect** | `mdrewriter-cli info` | `Device identified.` 以及固件 `1.1.0`（出厂固件则为 `1.0`） |
| 2 | 空插槽 | **Detect cartridge** | `mdrewriter-cli detect` | 没有找到闪存芯片；读取空插槽只得到 `0xFF` |
| 3 | 原装游戏，只读 | 插入卡带，**Detect cartridge**，**Cartridge size** 选 2 MiB（或游戏大小），**Read ROM…** | `mdrewriter-cli read-rom --size 2M --out game1.bin` | 生成转储文件（每 2 MiB 约 12.5 秒）。掩膜 ROM 卡带的 `detect` 显示 flash id `0000` 或 “unknown chip”：它**不是**闪存卡，绝不要写入 |
| 4 | 读两次并比较 | 再读一次同一卡带到 `game2.bin`，**Compare files…** | `mdrewriter-cli compare game1.bin game2.bin` | 没有差异。结果不同说明接触不良：清洁卡带金手指后重试 |
| 5 | 闪存卡：检测 | 插入闪存卡，**Detect cartridge** | `mdrewriter-cli detect` | `S29GL064N ... Supported`，以及一行 `Chip codes 017E1001（或 017E1000）, CFI sector words ...` |
| 6 | **备份闪存卡上现有的内容** | **Read ROM…** 2 MiB 和 **Read save…** | `read-rom --size 2M --out old.bin`，`read-save --size 32K --out old.srm` | 两个文件都生成了。如果卡里有你想要的东西就保存好 |
| 7 | 擦除 2 MiB | **Erase by size…**，**Cartridge size** 选 2 MiB，确认 | `mdrewriter-cli erase 2M --yes` | 6 到 9 秒内出现 `Erase complete.`；再读取只得到 `0xFF` |
| 8 | 写入 ROM（最大 2 MiB） | **Write ROM…**，选择 `.bin`/`.md`/`.gen`/`.smd`，保持 **Verify after writing** 勾选，确认 | `mdrewriter-cli write-rom game.bin --yes` | `Game written`，然后 `Verified: the … bytes read back match the file.` 2 MiB 约 90 秒 |
| 9 | 再次校验 | **Read ROM…**，再用 **Compare files…** 与原文件比较 | `mdrewriter-cli verify game.bin` | 完全一致 |
| 10 | 存档数据 | **Read save…** 两次，比较 | `read-save --size 32K --out s1.srm`，再读 `s2.srm`，`compare s1.srm s2.srm` | 两个文件一致 |

**不要**对非闪存卡、对存有你没有备份的游戏的卡带执行擦除和写入步骤，也不要在连接着其他东西时执行。

### 我们使用的测试套件（可选，只读）

测试台套件会读取开发板和卡带，**绝不写入也不擦除**（它没有 `--yes`）。需要 Python 3：

```
python3 tools/hwtest/hwtest.py nocart --port ttyACM0 --expect-fw 1.1          # 空插槽
python3 tools/hwtest/hwtest.py cart   --port ttyACM0 --expect-fw 1.1 --rom-size 2M   # 插入卡带
```

它会按检查项显示 PASS / FAIL / INFO / SKIP，并把报告保存到 `test-results/`。加上 `--rom-size 8M` 还会读取 8 MiB（在闪存卡上第二个 4 MiB 会重复第一个：正常，见第 8 节）。

## 8. 闪存卡的 2 MiB 限制

**KY / FlashKit 系列闪存卡最多只能存放 2 MiB 的游戏，无论芯片上印的容量是多少（S29GL064N 是 8 MiB）。** 我们试了两张（一张 KY 卡和另一张 S29GL064N 卡），表现完全一样：

- 在 2 MiB 以上擦除或写入都会失败：`erase 4M` 大约 23 秒后以 `A sector did not finish erasing in time` 停止，大于 2 MiB 的游戏无法写入。
- 读取 2 MiB 以上的区域看到的是**存档 RAM**（每隔一个字节为 `0xFF`），而不是闪存：卡带的电路板只在下半 2 MiB 选通闪存，上半 2 MiB 选通 RAM。读取 8 MiB 会把同样的 4 MiB 重复两次。

这是卡带电路板的设计（它的地址译码器，见 `docs/HWTEST.md`），不是 MD Rewriter、固件或程序的故障。任何设置都改变不了它；我们试过原装编程器的映射器寄存器。

**能放下的：** 几乎所有 Mega Drive 游戏（大多数在 512 KiB 到 2 MiB 之间；2 MiB 的 Metal Gear 已在两张卡上写入并校验）。**放不下的：** 大于 2 MiB 的游戏，例如 Super Street Fighter II（4 MiB，带分页映射器）。这些游戏需要另一种卡带：没有这种译码器的普通 4 MiB 闪存卡（例如开源设计 `MD-Flash-Cart-4MB`，MX29LV320 或 MX29L3211），或者带分页映射器的卡带。

## 9. 第一台设备上测试了什么

第一台设备，2026-11-13。固件 1.1.0-test（与 1.1.0 是同一个程序，只有版本文字不同）。

| 检查项 | 结果 |
|--------|------|
| 开发板 | 微控制器是 STM32F103xE，512 KiB 闪存（设计文件写的是 128 KiB 的型号）；固件 1.1 放得下 |
| 出厂固件备份 | 读取两次，一致，没有读保护。（`restore` 命令只在电脑上用模拟工具测试过；没有在设备上运行） |
| 通过 SWD 烧录固件 1.1 | 已写入并校验；开发板枚举为 `0483:5740` 并能与程序通信 |
| 空插槽 | 两次读取一致，只有 `0xFF` |
| 原装卡带（Rolling Thunder 2），只读 | 2 MiB 读取两次，用时 12.4 秒，一致，与固件 1.0 得到的相同。从未写入 |
| 闪存卡 S29GL064N，固件 1.0 | 只写入隔一个字的内容：需要修复轮次 |
| 闪存卡 S29GL064N 和一张 KY 卡，固件 1.1 | 识别为 `S29GL064N`；擦除 2 MiB 用时 6 到 9 秒；2 MiB 的 Metal Gear **一次**写入并校验（含读回约 90 秒）；转储与文件一致 |
| 写入后的卡带在真实主机上 | 机主在真实的 Mega Drive 上测试了用这个固件写入的卡带（2026-11-13 报告） |
| 不擦除直接覆盖数据 | 0.4 秒内出现 `WRITE TIMEOUT`，开发板继续响应：安全的失败方式 |
| 两张闪存卡芯片 ID 相同，但扇区布局不同 | 所以固件始终以小步长擦除，两种卡都能用 |
| 在 2 MiB 以上写入或擦除 | 这两张卡都不可能（第 8 节） |

尚未测试：SSF2 分页映射器读取、写入过程中断电、带写缓冲的版本，以及其他品牌的闪存卡。

## 10. 故障排除

| 现象 | 处理方法 |
|------|----------|
| 电脑看不到开发板 | 使用带数据线的 USB-A 转 USB-C 线。换一个 USB 口。POWER 灯必须亮 |
| “permission denied”（Linux） | `sudo usermod -aG dialout $USER`，重新登录，或安装 udev 规则 |
| `probe` 显示 `chip id 0x0` 或什么都找不到 | **先检查排针上的 GND**（针脚松动是常见原因），然后是 SWCLK 和 SWDIO，再按紧杜邦头。脚本会自动重试 |
| `swd.sh` 说芯片里不是备份过的固件 | 这是另一台设备，或者已被改动。先重新做备份；没有备份绝不烧录 |
| 烧录后开发板在 USB 上看不到 | 拔掉再插上开发板的 USB 线 |
| `detect` 显示未知芯片 | 不是闪存卡（是原装卡），或者芯片不在表中：不要写入 |
| “did not finish erasing” | 卡带不是闪存卡、已损坏，或者你要求超过了 2 MiB（第 8 节） |
| `WRITE TIMEOUT` | 该区域事先没有擦除（先擦除再写入），或者芯片已损坏 |
| 校验失败 | 清洁卡带金手指，换一根 USB 线，重复擦除和写入 |
| 同一张卡带两次读取结果不同 | 接触不良：用异丙醇清洁金手指后重新插入 |
| 写好的游戏在主机上不能启动 | 确认文件是有效的 ROM（程序会提示头部问题）、不超过 2 MiB，并且校验通过了 |

如果你遇到这里没有涉及的情况，请提交 issue，并附上程序日志和 `mdrewriter-cli detect` 的输出。
